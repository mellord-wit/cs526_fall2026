[Motivation]

FIBONACCI, THE OBVIOUS WAY
==========================

    def fib(n):
        if n <= 1:
            return n
        return fib(n - 1) + fib(n - 2)

To compute fib(40) = 102,334,155 it makes

331 million

function calls. Each step up in n multiplies the work by about 1.6:
exponential time.

Speaker notes:
  Start with code everyone has written. It is correct and it reads
  exactly like the math definition. Ask: how long does fib(40) take?
  In CPython it is tens of seconds; fib(50) would take hours. The
  exact count is 331,160,281 calls for fib(40); the example file
  prints the call counts so students can see them. The number of calls
  is 2·F(n+1) − 1, so it grows like the golden ratio, about 1.618 to
  the n. Ask: where is all that time going? Next slide answers it.

[Where the time goes]

THE SAME CALLS HAPPEN AGAIN AND AGAIN
=====================================

                          fib(5)
                 /                    \
             fib(4)                  [fib(3)]
           /        \               /       \
      [fib(3)]    {fib(2)}      {fib(2)}    fib(1)
      /     \      /    \        /    \
  {fib(2)} fib(1) fib(1) fib(0) fib(1) fib(0)
   /    \
fib(1) fib(0)

  [ ] = fib(3), computed 2 times    { } = fib(2), computed 3 times

15 calls for fib(5): fib(3) runs twice, fib(2) three times, fib(1)
five times.

Speaker notes:
  This is the recursion tree for fib(5). The orange boxes are fib(3),
  computed twice. The blue boxes are fib(2), computed three times.
  Point at the left subtree under fib(4): the whole fib(3) subtree on
  the right is an exact copy of work we already did on the left. The
  tree has 15 nodes for n = 5, and every extra level roughly doubles
  it. The key observation: there are only n + 1 different questions
  (fib(0) to fib(n)), but we ask them exponentially many times. That
  gap is what dynamic programming removes.

[The key idea]

TWO PROPERTIES MAKE A DP PROBLEM
================================

* Overlapping subproblems
    The naive recursion solves the same smaller problem many times.
    Fix: solve each one once and store the answer.

* Optimal substructure
    The best answer is built from the best answers to smaller
    problems.
    Result: we can write a recurrence.

Dynamic programming = recursion + a table of remembered answers.

Speaker notes:
  These are the two properties to check for. Overlapping subproblems:
  without it, caching gains nothing. Merge sort, for example, splits
  into halves that never repeat, so it is divide and conquer, not DP.
  Optimal substructure: the best solution contains best solutions to
  its subproblems. Shortest paths have it: the best route from A to C
  through B uses the best route from A to B. Longest simple path does
  not, which is why it has no easy DP. The name “dynamic programming”
  is historical: Richard Bellman chose it in the 1950s. “Programming”
  meant planning with a table, not writing code.

EXPANSION A: WHEN DP APPLIES, AND WHEN IT DOES NOT
----------------------------------------------------------------------

[2.5-hour plan · after slide 5 · 0:16-0:23, 7 minutes]

Slide 5 named the two properties. This block tests them on problems
students already know, including two where DP is the wrong tool.

A.1 No overlapping subproblems: merge sort
==========================================

Merge sort splits a list in half, sorts each half and merges. On a
list of 8 elements it makes 15 recursive calls, and all 15 work on
different ranges of the list. Every subproblem is new, so a memo
table would never get a single hit. Merge sort is divide and
conquer, not DP.

Compare Fibonacci: fib(30) makes 2,692,537 calls but there are only
31 different subproblems, fib(0) to fib(30). The gap between calls
and distinct subproblems is exactly what memoization removes.

    Quick test: count the distinct subproblems. If that number is
    much smaller than the number of recursive calls, DP will help.

A.2 No optimal substructure: the longest simple path
====================================================

Take four towns q, r, s, t joined in a ring: q-r, r-t, t-s, s-q.

* Shortest paths have optimal substructure
    A shortest path from q to t through r is made of a shortest path
    from q to r and a shortest path from r to t.
* Longest simple paths do not
    (A simple path never repeats a town.) The longest simple path
    from q to t is q-r-t, length 2. Its piece from q to r has
    length 1, but the longest simple path from q to r is q-s-t-r,
    length 3. Glue that onto r-t and the path visits t twice, which
    is not allowed.

The best answer to the big problem is not built from the best
answers to the small ones, so there is no recurrence to write. No
efficient algorithm is known for longest simple paths in general.

A.3 DP vs. greedy vs. divide and conquer
========================================

* Greedy
    Makes one choice per step and never undoes it. Example: making
    change with US coins (1, 5, 10, 25).
* Divide and conquer
    Splits the problem into independent pieces that never repeat.
    Example: merge sort.
* Dynamic programming
    Compares every choice, and stores the answers to overlapping
    subproblems so each is solved once. Example: making change with
    coins [1, 3, 4].

Greedy is fastest when it is correct, but it needs a proof that the
locally best choice is always safe. DP needs no such proof: it tries
every choice, and the table makes that affordable.

A.4 Quick check for the class
=============================

Ask for a show of hands on each one.

* Binary search
    Not DP. Each step discards half; no subproblem repeats.
* Counting right/down paths in a grid
    DP. paths(r, c) is reached from many different routes.
* Finding the maximum of a list
    Not DP. One pass, nothing repeats.
* Fewest coins for an amount
    DP, unless the coin system is one where greedy is proven safe.

Teaching notes:
  Draw the four-town ring on the board; the longest-path example is
  short but surprises most students. The table in A.3 is a good
  place to restate that DP is "try everything, but remember".

[Approach 1 · Top-down]

MEMOIZATION: RECURSE, THEN CACHE
================================

    def fib(n, memo=None):
        if memo is None:
            memo = {} # new dict for each top call
        if n in memo: # solved already?
            return memo[n]
        if n <= 1: # base cases
            return n
        memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
        return memo[n]

* O(n) time
    Each fib(k) is computed once. fib(40) now takes 79 calls.

* O(n) space
    The memo dict plus the call stack.

* Python shortcut
    Put @functools.lru_cache on the plain recursive version.

Speaker notes:
  Memoization keeps the recursive code and adds a lookup table. Before
  doing any work we check the table; after doing the work we store the
  result. The recursion still happens top-down, starting from n, but
  each subproblem is solved only once. Count: fib(40) makes 79 calls
  instead of 331 million (each of fib(2)..fib(40) does real work once,
  plus the cache hits). Point out memo=None: writing memo={} as a
  default argument is a classic Python trap, because that one dict is
  shared between all calls of the function. It happens to work here,
  but it is a bug waiting to happen in other problems. Mention that
  HW5’s lais1.py already used this pattern: the longest_lengths_of_a
  and longest_lengths_of_b lists start at −1 and act as memo tables.
  The functools.lru_cache decorator does the same caching for you on
  any function whose arguments are hashable.

[Approach 2 · Bottom-up]

TABULATION: FILL A TABLE IN ORDER
=================================

    def fib(n):
        if n <= 1:
            return n
        table = [0] * (n + 1) # table[i] = fib(i)
        table[1] = 1
        for i in range(2, n + 1): # small to large
            table[i] = table[i - 1] + table[i - 2]
        return table[n]

* No recursion
    A loop fills the table from the base cases up.

* Same O(n) time
    No call overhead, no recursion limit.

* O(1) space is possible
    Each cell needs only the last two, so keep two variables.

Speaker notes:
  Tabulation turns the recursion inside out. We decide in advance
  which order to solve subproblems in, smallest first, so that
  whenever we need table[i − 1] and table[i − 2] they are already
  filled. Draw the table on the board: 0, 1, 1, 2, 3, 5, 8, 13 filling
  left to right. Because each cell only looks back two places, we can
  throw the rest of the table away. The example file has fib_two_vars:
  prev, curr = 0, 1; then loop n times doing prev, curr = curr, prev +
  curr; return prev. That is O(n) time and O(1) space. Saving space
  this way is common in bottom-up DP: if row i only needs row i − 1,
  keep two rows.

[Choosing a style]

TOP-DOWN VS. BOTTOM-UP
======================

                  Top-down (memoization)        Bottom-up (tabulation)
----------------  ----------------------------  ----------------------
How you write it  Recursion plus a cache        Loops that fill a
                                                table
Order of work     Set by the recursion          You choose it
                                                explicitly
Solves            Only subproblems it needs     Every cell in the
                                                table
Overhead          Calls; depth limit near 1000  None; easy to cut
                                                space
Use it when       The recurrence is natural     All states are needed

Both give the same answers and the same big-O time. A good habit:
write top-down first to get it right, then convert to bottom-up.

Speaker notes:
  Neither style is “the real DP”; both are. Top-down is often easier
  to get right because it mirrors the recurrence, and it skips states
  that are never reached. Bottom-up avoids Python’s default recursion
  limit of 1000 frames (sys.getrecursionlimit()), so memoized
  fib(5000) raises RecursionError while the loop version is fine.
  Bottom-up also makes space savings visible. Suggest the workflow:
  recurrence first, memoize to test it, then convert to a table if
  speed or depth matters. That is about 20 minutes in; next is the
  recipe.

B.2 Looking inside the cache
============================

    fib_lru(40)
    fib_lru.cache_info()
    # CacheInfo(hits=38, misses=41, maxsize=None, currsize=41)

41 misses: fib(0) through fib(40) are each computed once. 38 hits:

B.3 Hitting the recursion limit
===============================

    import sys
    sys.getrecursionlimit()  # 1000 by default
    fib_memo(5000)           # RecursionError
    fib_table(5000)          # fine: a number with 1045 digits

Memoization recurses n levels deep. sys.setrecursionlimit can raise
the limit, but very deep recursion can still crash the interpreter,
so for large n the bottom-up loop is the reliable fix.

B.4 Hand-trace exercise (2 minutes)
===================================

Ask: when fib_memo(5) runs, in what order are entries ADDED to the
memo dict? Students often answer 5, 4, 3, 2. The real order is
2, 3, 4, 5: the recursion dives down to the base cases first, and
results are stored on the way back up. So top-down code still fills
the table bottom-up, which is a good bridge to slide 7.

[The recipe]

FIVE STEPS FOR ANY DP PROBLEM
=============================

* 1. Define the subproblem
    Say in words what dp[i] or dp[i][j] means.

* 2. Write the recurrence
    Express one subproblem using smaller ones.

* 3. Set the base cases
    Answer the smallest inputs directly.

* 4. Pick an order
    Fill cells so every dependency is ready first.

* 5. Read the answer
    Find it in the table, then trace back the choices.

Step 1 is the hard part. If you can say what dp[i] means in one
sentence, the rest usually follows.

Speaker notes:
  Apply the recipe to Fibonacci out loud so students see it once on an
  easy problem. 1: table[i] is the i-th Fibonacci number. 2: table[i]
  = table[i − 1] + table[i − 2]. 3: table[0] = 0, table[1] = 1. 4:
  increasing i. 5: the answer is table[n]. Stress step 1. Most wrong
  DP solutions come from a vague subproblem. Students should write the
  meaning of the table as a comment in their code, the way the
  tabulation slide did. We will use these five steps, labelled, on
  each of the next three examples.

[Example 1 · Coin change]

MAKE CHANGE WITH THE FEWEST COINS
=================================

Coins [1, 3, 4], as many of each as you like. Make 6.

* Greedy: take the biggest coin that fits
      4 + 1 + 1
    3 coins. Not optimal.

* DP: try every last coin
      3 + 3
    2 coins. Optimal.

Speaker notes:
  About 23 minutes in. Pose the problem before showing the answers and
  ask the class for the fewest coins. Many will say 3 (4 + 1 + 1)
  because that is what greedy does, and greedy works for US coins (1,
  5, 10, 25). With 1, 3, 4 it fails: 3 + 3 uses only 2 coins. This is
  the point of the example: when a greedy choice can be wrong, we need
  to consider every choice, and DP makes that affordable. The DP idea:
  whatever the best solution is, it has some last coin c. Remove it,
  and what remains must be a best solution for amount − c. That is
  optimal substructure.

[Example 1 · Coin change]

SUBPROBLEM, RECURRENCE, TABLE
=============================

Subproblem: dp[a] = the fewest coins that add up to exactly a.

    dp[0] = 0
    dp[a] = min( dp[a - c] + 1 ) over each coin c <= a
    dp[6] = min(dp[5]+1, dp[3]+1, dp[2]+1) = min(3, 2, 3) = 2

a          0  1  2  3  4  5  6
---------  -  -  -  -  -  -  -
dp[a]      0  1  2  1  1  2  2
last coin  .  1  1  3  4  1  3

Speaker notes:
  Walk the recipe. 1, subproblem: dp[a] is the fewest coins making
  exactly a. 2, recurrence: try each coin c as the last coin; the rest
  costs dp[a − c]; take the minimum and add 1. 3, base case: dp[0] =
  0, and any amount we cannot make stays at infinity. 4, order: a from
  1 up to the target, because dp[a] only looks at smaller amounts. 5,
  answer: dp[6] = 2. Fill the table live on the board, one column at a
  time, asking students for each value. The “last coin” row records
  which coin won, and it lets us rebuild the solution: from 6 take a
  3, go to dp[3], take a 3, reach 0. So the coins are 3 + 3.

[Example 1 · Coin change]

COIN CHANGE IN PYTHON
=====================

    def min_coins(coins, amount):
        INF = float("inf")
        dp = [0] + [INF] * amount # dp[0] = 0
        for a in range(1, amount + 1):
            for c in coins:
                if c <= a and dp[a - c] + 1 < dp[a]:
                    dp[a] = dp[a - c] + 1
        return dp[amount] if dp[amount] != INF else -1
    
    min_coins([1, 3, 4], 6)  # 2

* Time O(A · k)
    A amounts, each tries k coins.

* Space O(A)
    One list of length A + 1.

* Impossible amounts
    Stay at infinity, so we return −1.

Speaker notes:
  The code is the recurrence almost word for word. The outer loop is
  the evaluation order; the inner loop tries every last coin. Using
  infinity for “not reachable yet” means we never need a special case:
  infinity + 1 is still infinity in Python floats. Example: coins [5,
  10] and amount 3 returns −1. Quick variation to ask: how would you
  count the number of ways to make the amount instead of the fewest
  coins? Answer: replace min with a sum, set ways[0] = 1, and loop
  over coins in the outer loop so that each combination is counted
  once and not once per ordering. That is about 32 minutes in.

EXPANSION C: COUNTING WAYS: COMBINATIONS VS. ORDERINGS
----------------------------------------------------------------------

[2.5-hour plan · after slide 12 · 0:48-0:54, 6 minutes]

Change the question on slide 10: instead of the fewest coins, how
many ways are there to make 6 from coins [1, 3, 4]? That depends on
whether order matters, and the only difference in the code is which
loop is on the outside.

C.1 Two versions, one swap
==========================

    def count_combinations(coins, amount):
        ways = [1] + [0] * amount       # one way to make 0
        for c in coins:                 # coins outside
            for a in range(c, amount + 1):
                ways[a] += ways[a - c]
        return ways[amount]

    def count_sequences(coins, amount):
        ways = [1] + [0] * amount
        for a in range(1, amount + 1):  # amounts outside
            for c in coins:
                if c <= a:
                    ways[a] += ways[a - c]
        return ways[amount]

    count_combinations([1, 3, 4], 6)  # 4
    count_sequences([1, 3, 4], 6)     # 9

The 4 combinations are 1+1+1+1+1+1, 1+1+1+3, 1+1+4 and 3+3. The 9
sequences count 1+1+4, 1+4+1 and 4+1+1 separately, and so on.

C.2 Why the loop order matters
==============================

* Coins outside
    When coin c is processed, ways[] only knows about coins earlier
    in the list. Every combination is built in one fixed order
    (all 1s, then 3s, then 4s), so it is counted once.
* Amounts outside
    For each amount, the last coin can be any coin, and the rest
    can be anything. 1+4 and 4+1 have different last coins, so both
    are counted.

The table after each coin (coins outside):

Amount          0  1  2  3  4  5  6
--------------  -  -  -  -  -  -  -
coin 1 only     1  1  1  1  1  1  1
coins 1, 3      1  1  1  2  2  2  3
coins 1, 3, 4   1  1  1  2  3  3  4

Sequences       1  1  1  2  4  6  9

Ask students to check one cell by listing: ways to make 4 as
sequences are 1+1+1+1, 1+3, 3+1 and 4, so 4.

Teaching notes:
  This is the "loop direction matters" idea of discussion section 7
  in its first form. Students who meet both versions here find the
  0/1 vs. unbounded knapsack loops on slide 32 much easier.

[Example 2 · 0/1 knapsack]

PACK THE MOST VALUE INTO CAPACITY 7
===================================

Item  Weight  Value
----  ------  -----
A     1       1
B     3       4
C     4       5
D     5       7

Each item is taken whole or left behind (0 or 1 of it).

Subproblem: K[i][c] = the best value using only the first i items with
capacity c.

    skip = K[i-1][c]
    take = K[i-1][c - w[i]] + v[i] # if w[i] <= c
    K[i][c] = max(skip, take)
    K[0][c] = 0 # no items, no value

Speaker notes:
  About 32 minutes in. Ask first: which items would you pack? Students
  often grab D, the most valuable item (7), then can only add A for a
  total of 8. The best is B + C: weight exactly 7, value 9. Greedy by
  value per weight also fails here: A is 1.0, B 1.33, C 1.25, D 1.4,
  so greedy takes D and then A, for 8. Now the recurrence. Consider
  item i last. Either we skip it, and the answer is the best with the
  first i − 1 items and the same capacity, or we take it, gaining v[i]
  and losing w[i] of capacity. Two choices, take the better one. The
  table now has two dimensions because the subproblem needs two
  numbers to describe it: how many items we may use, and how much room
  is left.

[Example 2 · 0/1 knapsack]

FILLING THE TABLE ROW BY ROW
============================

items \ c  0  1  2  3  4  5  6  7
---------  -  -  -  -  -  -  -  -
none       0  0  0  0  0  0  0  0
+A (1, 1)  0  1  1  1  1  1  1  1
+B (3, 4)  0  1  1  4  5  5  5  5
+C (4, 5)  0  1  1  4  5  6  6  9
+D (5, 7)  0  1  1  4  5  7  8  9

    K[C][7] = max( skip K[B][7] = 5,  take K[B][3] + 5 = 9 ) = 9

Speaker notes:
  Fill this on the board one row at a time. Row “none” is all zeros:
  the base case. Row +A: once capacity is at least 1, we can take A
  for value 1. Row +B: at capacity 3 we take B for 4; at 4 we take B
  and A for 5. The interesting cell is row +C, capacity 7, in orange.
  Skipping C leaves the row-B value at capacity 7, which is 5. Taking
  C uses 4 of the 7 units, leaving capacity 3, where row B says 4;
  plus C’s value 5 gives 9. The blue cells are the two values that
  cell compares. The last row adds D, but at capacity 7 taking D gives
  K[C][2] + 7 = 8, which is worse than 9, so the answer stays 9. Each
  cell looks only at the row above, so row order is a valid evaluation
  order. Size: (n + 1) × (C + 1) cells, each O(1), so O(n·C) time.
  Note that this is pseudo-polynomial: it depends on the numeric
  capacity, not just the number of items.

[Example 2 · 0/1 knapsack]

KNAPSACK IN PYTHON
==================

    def knapsack(weights, values, cap):
        n = len(weights)
        K = [[0] * (cap + 1) for _ in range(n + 1)]
        for i in range(1, n + 1):
            w, v = weights[i - 1], values[i - 1]
            for c in range(cap + 1):
                K[i][c] = K[i - 1][c] # skip item i
                if w <= c: # or take it
                    take = K[i - 1][c - w] + v
                    K[i][c] = max(K[i][c], take)
        return K[n][cap]
    
    knapsack([1, 3, 4, 5], [1, 4, 5, 7], 7)  # 9

* Time O(n · C)
    One O(1) step per cell.

* Space O(n · C)
    Keep the whole table to recover the items.

* Watch the index
    Row i uses weights[i − 1].

Speaker notes:
  Point out the off-by-one: the table has n + 1 rows so that row 0 can
  be the “no items” base case, which means row i describes item i − 1
  in the Python lists. Ask: why must the inner loop read from row i −
  1 and not row i? Because reading row i would let us take the same
  item twice. That other version is the unbounded knapsack, where
  every item can be reused, and it is the same code with K[i][c − w]
  instead of K[i − 1][c − w]. If you only need the value, you can keep
  a single 1-D list and loop c downward from cap to w; looping
  downward is what keeps each item to one use. To list the chosen
  items, keep the full table: next slide.

TRACING BACK WHICH ITEMS WE TOOK
================================

    def chosen_items(K, weights, cap):
        items, c = [], cap
        for i in range(len(weights), 0, -1):
            if K[i][c] != K[i - 1][c]: # changed
                items.append(i - 1) # so taken
                c -= weights[i - 1]
        return items[::-1]

D: 9 = 9 above, so skip

C: 9 ≠ 5, take; c = 7 − 4 = 3

B: 4 ≠ 1, take; c = 3 − 3 = 0

A: 0 = 0, skip

Result: B + C, weight 7, value 9

Speaker notes:
  The table stores values, not decisions, but the decisions can be
  recovered. Start at the bottom-right cell. If K[i][c] is the same as
  the cell straight above it, item i was not needed, so move up. If it
  is different, item i must have been taken, so record it, subtract
  its weight from c, and move up. Walk it on the table from the
  previous slide: D is skipped, C is taken, capacity drops to 3, B is
  taken, capacity drops to 0, A is skipped. This is step 5 of the
  recipe, and the same trick works for coin change (the last-coin row)
  and for LCS next. About 44 minutes in.

D.1 The problem (give students 3 minutes)
=========================================

Can [1, 5, 11, 5] be split into two groups with the same sum? Ask

D.2 The solution
================

The total is 22, so each group must sum to 11. The question becomes:
is there a subset that sums to exactly 11? That is a knapsack in
which each item's value equals its weight, and we only ask yes or
no.

    Subproblem: can[s] = True if some subset of the numbers seen so
                far adds up to exactly s
    Recurrence: can[s] = can[s] or can[s - x], for each number x
    Base case:  can[0] = True (the empty subset)
    Order:      numbers one at a time; s downward (each number once)
    Answer:     can[total // 2]

    def can_partition(nums):
        total = sum(nums)
        if total % 2:
            return False            # an odd total cannot split
        half = total // 2
        can = [True] + [False] * half
        for x in nums:
            for s in range(half, x - 1, -1):
                if can[s - x]:
                    can[s] = True
        return can[half]

    can_partition([1, 5, 11, 5])  # True: {11} and {1, 5, 5}
    can_partition([1, 2, 3, 5])   # False: the total 11 is odd

D.3 Trace on the board

Reachable sums (up to 11) after each number:

After  Reachable sums
-----  ---------------------
start  0
1      0, 1
5      0, 1, 5, 6
11     0, 1, 5, 6, 11
5      0, 1, 5, 6, 10, 11

11 is reachable, so the answer is yes. It already became reachable
after the third number (11 on its own).

=====================================

  X: B A C D B

Subproblem: L[i][j] = LCS length of the first i letters of X and the
first j letters of Y.

    # i = 0 or j = 0:
    L[i][j] = 0
    # last letters match:
    L[i][j] = L[i-1][j-1] + 1
    # otherwise drop one:
    L[i][j] = max(L[i-1][j], L[i][j-1])

Speaker notes:
  About 44 minutes in. Define subsequence versus substring: a
  substring must be contiguous, a subsequence only needs to keep the
  order. B C B is a subsequence of BACDB (skip A and D) and of BDCB
  (skip D). B D B also works, which shows the LCS is not always
  unique, though its length is. Applications: diff and git compare
  files line by line with LCS, and DNA sequence alignment uses close
  relatives of it. The recurrence comes from looking at the last
  letters. If they match, that letter can end the LCS, so we take 1
  plus the LCS of both prefixes without it. If they do not match, at
  least one of the two last letters is not in the LCS, so we drop one
  or the other and keep the better answer.

[Example 3 · Longest common subsequence]

LCS IN PYTHON
=============

    def lcs_length(x, y):
        m, n = len(x), len(y)
        L = [[0] * (n + 1) for _ in range(m + 1)]
        for i in range(1, m + 1):
            for j in range(1, n + 1):
                if x[i - 1] == y[j - 1]:
                    L[i][j] = L[i - 1][j - 1] + 1
                else:
                    L[i][j] = max(L[i - 1][j], L[i][j - 1])
        return L[m][n]
    
    lcs_length("BACDB", "BDCB")  # 3

* Time O(m · n)
    One O(1) step per cell.

* Space O(m · n)
    Two rows suffice for the length alone.

* Brute force
    x has 2^m subsequences: exponential.

Speaker notes:
  Same shape as knapsack: a table one bigger than the inputs in each
  dimension, a double loop, and an off-by-one where row i means the
  letter x[i − 1]. Contrast with brute force: a string of length m has
  2^m subsequences, so checking each one against y is exponential,
  while the table is m·n. For two 1,000-character strings that is one
  million cells, instant. The example file has lcs_string, which does
  the trace back and returns the actual subsequence. About 53 minutes
  in.

EXPANSION E: WORKED EXAMPLE: EDIT DISTANCE

[2.5-hour plan · after slide 19 · 1:31-1:40, 9 minutes]

E.1 The recurrence
==================

The edit distance between two words is the fewest single-letter
inserts, deletes and substitutions that turn one into the other.

    Subproblem: d[i][j] = edit distance from a[:i] to b[:j]
    Base cases: d[i][0] = i (delete all i letters)
                d[0][j] = j (insert all j letters)
    Recurrence: if a[i-1] == b[j-1]: d[i][j] = d[i-1][j-1]
                otherwise d[i][j] = 1 + min(
                    d[i-1][j],      # delete a[i-1]
                    d[i][j-1],      # insert b[j-1]
                    d[i-1][j-1])    # substitute a[i-1] -> b[j-1]

E.2 The table for "kitten" to "sitting"
=======================================

       -  s  i  t  t  i  n  g
    -  0  1  2  3  4  5  6  7
    k  1  1  2  3  4  5  6  7
    i  2  2  1  2  3  4  5  6
    t  3  3  2  1  2  3  4  5
    t  4  4  3  2  1  2  3  4
    e  5  5  4  3  2  2  3  4
    n  6  6  5  4  3  3  2  3

The answer is the bottom-right cell: 3. Fill a few cells with the
class. Row k, column s: the letters differ, so 1 + min(1, 1, 0) = 1
(substitute). Row i, column i: the letters match, so copy the
diagonal: 1.

E.3 Code with trace back
========================

    def edit_table(a, b):
        m, n = len(a), len(b)
        d = [[0] * (n + 1) for _ in range(m + 1)]
        for i in range(m + 1):
            d[i][0] = i
        for j in range(n + 1):
            d[0][j] = j
        for i in range(1, m + 1):
            for j in range(1, n + 1):
                if a[i - 1] == b[j - 1]:
                    d[i][j] = d[i - 1][j - 1]
                else:
                    d[i][j] = 1 + min(d[i - 1][j], d[i][j - 1],
                                      d[i - 1][j - 1])
        return d

    def edit_ops(a, b):
        d = edit_table(a, b)
        i, j, ops = len(a), len(b), []
        while i > 0 or j > 0:
            same = i > 0 and j > 0 and a[i - 1] == b[j - 1]
            if same and d[i][j] == d[i - 1][j - 1]:
                i, j = i - 1, j - 1                  # keep it
            elif i > 0 and j > 0 and d[i][j] == d[i - 1][j - 1] + 1:
                ops.append(f"substitute {a[i - 1]} -> {b[j - 1]}")
                i, j = i - 1, j - 1
            elif i > 0 and d[i][j] == d[i - 1][j] + 1:
                ops.append(f"delete {a[i - 1]}")
                i -= 1
            else:
                ops.append(f"insert {b[j - 1]}")
                j -= 1
        return ops[::-1]

    edit_ops("kitten", "sitting")
    # ['substitute k -> s', 'substitute e -> i', 'insert g']

Time and space are O(m·n), like LCS. Spell checkers and DNA
comparison use this distance; diff tools use a close relative.

Teaching notes:
  Ask what changes from LCS: the base row and column are no longer
  0, a match costs 0 instead of adding 1, and min replaces max. The
  same trace-back idea as slide 16 recovers the actual edits.

EXPANSION F: INTERVAL DP: MATRIX-CHAIN MULTIPLICATION
----------------------------------------------------------------------

[2.5-hour plan · after expansion E · 1:40-1:47, 7 minutes]

Slide 20 lists interval DP as a common shape but the lecture never
shows one. This is the standard example.

F.1 The problem
===============

Multiplying a p x q matrix by a q x r matrix takes p·q·r
multiplications. For a chain of matrices, the answer is the same in
any grouping, but the cost is not. With shapes A: 10 x 30,
B: 30 x 5 and C: 5 x 60:

    (A B) C = 10·30·5 + 10·5·60  =  1,500 +  3,000 =  4,500
    A (B C) = 30·5·60 + 10·30·60 =  9,000 + 18,000 = 27,000

Six times the work for the wrong grouping. With n matrices there
are exponentially many groupings, so we need DP.

F.2 The recurrence
==================

    Subproblem: m[i][j] = fewest multiplications to compute the
                product of matrices i through j
    Base case:  m[i][i] = 0 (one matrix, nothing to do)
    Recurrence: m[i][j] = min over i <= k < j of
                m[i][k] + m[k+1][j] + p[i-1]·p[k]·p[j]
                (split after matrix k, then multiply the two halves)
    Order:      by chain length, shortest first, since each cell
                needs only shorter intervals
    Answer:     m[1][n]

The fill order is the new idea: not row by row, but diagonal by
diagonal, from length 2 up to length n.

    def matrix_chain(p):
        """Matrix i has shape p[i-1] x p[i], for i = 1..n."""
        n = len(p) - 1
        m = [[0] * (n + 1) for _ in range(n + 1)]
        for length in range(2, n + 1):      # shorter chains first
            for i in range(1, n - length + 2):
                j = i + length - 1
                m[i][j] = min(
                    m[i][k] + m[k + 1][j] + p[i - 1] * p[k] * p[j]
                    for k in range(i, j))
        return m[1][n]

    matrix_chain([10, 30, 5, 60])        # 4500
    matrix_chain([40, 20, 30, 10, 30])   # 26000

F.3 The table for four matrices
===============================

For shapes 40 x 20, 20 x 30, 30 x 10 and 10 x 30:

m[i][j]  j=1   j=2     j=3     j=4
-------  ---   ------  ------  ------
i=1      0     24000   14000   26000
i=2            0       6000    12000
i=3                    0       9000
i=4                            0

The best grouping is (A1 (A2 A3)) A4: 6000 + 8000 + 12000 = 26000.
There are n^2/2 cells and each tries up to n splits: O(n^3) time.

F.4 Another interval DP
=======================

The longest palindromic subsequence uses the same shape:
L[i][j] = L[i+1][j-1] + 2 if s[i] == s[j], else
max(L[i+1][j], L[i][j-1]), filled by length. For "BBABCBCAB" it
is 7 ("BABCBAB"). Good homework, since students can check it by
hand.

DISCUSSION: MULTIDIMENSIONAL DYNAMIC PROGRAMMING
----------------------------------------------------------------------

[Extension after slide 19 · slides 24-43 · 2.5-hour plan: 1:47-2:30,
 see the lecture plan for shorter versions]

This discussion builds on the knapsack and LCS tables. Use it right
after slide 19 if time allows, or as the start of a follow-up class.
Sections 1-6 cover tables with several indices. Section 7 covers
techniques for saving space, and section 8 covers complex constraints:
how to tweak the state definition and how to make transitions
faster. The code below is self-contained and has been checked against
brute force.

1. WHAT "DIMENSION" MEANS
=========================

The dimension of a DP is the number of indices needed to name one
subproblem. Each index is a state variable: one piece of information
you must know in order to finish the problem from that point.

Problem                    State        Dimensions
-------------------------  -----------  ------------------------------
Fibonacci, coin change     dp[i]        1
0/1 knapsack               K[i][c]      2 (items used, room left)
LCS of two strings         L[i][j]      2 (prefix of x, prefix of y)
LCS of three strings       L[i][j][k]   3
Knapsack, weight + volume  K[i][w][v]   3
Floyd-Warshall paths       d[k][i][j]   3
Traveling salesperson      dp[mask][j]  2, but mask has 2^n values

Everything in the lecture so far was 1-D or 2-D. Nothing changes in
the method when there are more indices: the five-step recipe is the
same. What changes is how you choose the state, how big the table
gets, and what order to fill it in.

2. CHOOSING THE STATE
=====================

Ask this question: "If I stopped halfway, what would I have to write
down so that someone else could finish the job optimally?" Each
independent item on that list becomes one dimension.

Example: in 0/1 knapsack, after deciding about the first i items, the
best way to finish depends only on i and on the capacity that is
left. It does not depend on which items were chosen. So (i, c) is
enough. Add a volume limit, and the remaining volume matters too, so
the state grows to (i, w, v).

A test for a missing dimension: if two different histories reach the
same state but need different decisions from there on, the state is
missing a piece of information.

3. COST: COUNT THE CELLS
========================

    time  = (number of states) x (work per state)
    space = (number of states), often reducible (section 7)

The number of states is the product of the ranges of the indices.

* LCS of three strings of length 100
    101 x 101 x 101 = about 1 million cells, O(1) work each.
* Knapsack with n = 100 items, W = 1000, V = 1000
    101 x 1001 x 1001 = about 100 million cells: slow in Python.

Every new dimension multiplies the table size by its range. This is
the "curse of dimensionality": add only the dimensions you need.

4. FILL ORDER WITH SEVERAL INDICES
==================================

Each cell may read only cells that are already filled. The general
rule: find an order of the states so that every arrow in the
recurrence points backward to a state that has been computed.

* Every index only decreases (LCS, knapsack)
    Nested loops with each index increasing work, in any nesting
    order.
* Interval DP, dp[i][j] over x[i..j]
    A cell depends on shorter intervals, so loop over the interval
    length first, then the start i.
* Floyd-Warshall
    The k loop ("may use cities 0..k as stops") must be outermost.
* Memoization
    Sidesteps the question: the recursion discovers the order. With
    many dimensions it is often the easiest correct first version.

5. WORKED EXAMPLE: LCS OF THREE STRINGS
=======================================

Step 1, subproblem: L[i][j][k] = length of the longest subsequence
common to a[:i], b[:j] and c[:k].

Steps 2 and 3, recurrence and base case:

    # i = 0 or j = 0 or k = 0:
    L[i][j][k] = 0
    # all three last letters equal:
    L[i][j][k] = L[i-1][j-1][k-1] + 1
    # otherwise drop the last letter of one string:
    L[i][j][k] = max(L[i-1][j][k], L[i][j-1][k], L[i][j][k-1])

Step 4, order: i, j and k all increasing (every dependency has
smaller indices). Step 5, answer: L[p][q][r].

    def lcs3(a, b, c):
        p, q, r = len(a), len(b), len(c)
        L = [[[0] * (r + 1) for _ in range(q + 1)]
             for _ in range(p + 1)]
        for i in range(1, p + 1):
            for j in range(1, q + 1):
                for k in range(1, r + 1):
                    if a[i - 1] == b[j - 1] == c[k - 1]:
                        L[i][j][k] = L[i - 1][j - 1][k - 1] + 1
                    else:
                        L[i][j][k] = max(L[i - 1][j][k],
                                         L[i][j - 1][k],
                                         L[i][j][k - 1])
        return L[p][q][r]

    lcs3("BACDB", "BDCB", "BCDB")  # 3  (BCB or BDB)

The table has 6 x 5 x 5 = 150 cells: time and space O(p·q·r).

The same thing top-down, with the cache keyed by (i, j, k):

    from functools import lru_cache

    def lcs3_memo(a, b, c):
        @lru_cache(maxsize=None)
        def L(i, j, k):
            if i == 0 or j == 0 or k == 0:
                return 0
            if a[i - 1] == b[j - 1] == c[k - 1]:
                return L(i - 1, j - 1, k - 1) + 1
            return max(L(i - 1, j, k), L(i, j - 1, k), L(i, j, k - 1))
        return L(len(a), len(b), len(c))

Why not run 2-string LCS twice? Because the first LCS may be the wrong
one. With a = "AB", b = "BA", c = "B": the LCS of a and b can be "A"
or "B". If it picks "A", comparing with c gives 0, but the true answer
is 1 ("B"). The third dimension is needed to keep all the options
open.

6. WORKED EXAMPLE: KNAPSACK WITH TWO LIMITS
===========================================

Use the lecture's items again, and give each one a volume:

Item  Weight  Volume  Value
----  ------  ------  -----
A     1       4       1
B     3       1       4
C     4       3       5
D     5       2       7

Subproblem: K[i][w][v] = the best value using only the first i items
with weight at most w and volume at most v.

    skip = K[i-1][w][v]
    take = K[i-1][w - wt[i]][v - vol[i]] + val[i]   # if both fit
    K[i][w][v] = max(skip, take)

    def knapsack2(weights, volumes, values, W, V):
        n = len(weights)
        K = [[[0] * (V + 1) for _ in range(W + 1)]
             for _ in range(n + 1)]
        for i in range(1, n + 1):
            wt, vol = weights[i - 1], volumes[i - 1]
            val = values[i - 1]
            for w in range(W + 1):
                for v in range(V + 1):
                    K[i][w][v] = K[i - 1][w][v]
                    if wt <= w and vol <= v:
                        take = K[i - 1][w - wt][v - vol] + val
                        K[i][w][v] = max(K[i][w][v], take)
        return K[n][W][V]

    knapsack2([1, 3, 4, 5], [4, 1, 3, 2], [1, 4, 5, 7], 7, 4)  # 9
    knapsack2([1, 3, 4, 5], [4, 1, 3, 2], [1, 4, 5, 7], 7, 3)  # 7

With volume limit 4, B + C still fits (weight 7, volume 4), value 9.
With volume limit 3, B + C is too bulky, and the best is D alone,
value 7. One extra constraint, one extra dimension: O(n·W·V) time.

7. SPACE OPTIMIZATION TECHNIQUES
================================

A full table is the easiest way to get a DP right, and you need it
for trace back. Once the answers are correct, the table can often be
made much smaller. Every technique in this section starts from one
question:

    Which earlier cells does a cell read?

Call that set the cell's dependency window. A value that no remaining
cell will ever read can be thrown away.

7.1 Keep a few variables (a fixed-size window)
----------------------------------------------

If dp[i] reads only dp[i-1] and dp[i-2], two variables are enough.
fib_two_vars on slide 7 does this. Another example is the largest sum
of elements with no two adjacent ones chosen:

    def max_non_adjacent(nums):
        take, skip = 0, 0   # best so far with / without the last one
        for x in nums:
            take, skip = skip + x, max(take, skip)
        return max(take, skip)

    max_non_adjacent([2, 7, 9, 3, 1])  # 12  (2 + 9 + 1)

O(n) space becomes O(1). The tuple assignment matters: both new
values are computed from the old ones before either variable
changes. Writing take = skip + x on its own line first would feed
the new take into the max on the next line.

7.2 Rolling rows (two layers)
-----------------------------

If row i reads only row i - 1, keep two rows and swap them.

    def lcs_two_rows(x, y):
        if len(y) > len(x):
            x, y = y, x         # keep the rows as short as possible
        prev = [0] * (len(y) + 1)
        for i in range(1, len(x) + 1):
            curr = [0] * (len(y) + 1)
            for j in range(1, len(y) + 1):
                if x[i - 1] == y[j - 1]:
                    curr[j] = prev[j - 1] + 1
                else:
                    curr[j] = max(prev[j], curr[j - 1])
            prev = curr
        return prev[len(y)]

    lcs_two_rows("BACDB", "BDCB")  # 3

Space drops from O(m·n) to O(min(m, n)). The swap on the first lines
is a technique of its own: put the shorter sequence along the row.
For strings of length 1,000,000 and 100, that is two rows of 101
cells instead of two rows of 1,000,001.

A common variant allocates the two rows once and indexes them with
i % 2, as in L[i % 2][j]. It does the same thing without allocating
a new list on every pass.

7.3 One row, updated in place
-----------------------------

Sometimes a single row is enough, as long as you know which cells
have already been overwritten in the current pass. The loop direction
decides that.

0/1 knapsack reads best[c - w] from the PREVIOUS item's row. Looping
c downward means best[c - w] has not been updated for the current
item yet, so it still holds the old value:

    def knapsack_1d(weights, values, cap):
        best = [0] * (cap + 1)
        for w, v in zip(weights, values):
            for c in range(cap, w - 1, -1):     # downward
                best[c] = max(best[c], best[c - w] + v)
        return best[cap]

Loop upward instead, and best[c - w] may already include the current
item, so the item can be used again. That is exactly the unbounded
knapsack, where reuse is allowed:

    def knapsack_unbounded(weights, values, cap):
        best = [0] * (cap + 1)
        for w, v in zip(weights, values):
            for c in range(w, cap + 1):         # upward
                best[c] = max(best[c], best[c - w] + v)
        return best[cap]

    knapsack_1d([2], [3], 4)         # 3: the item once
    knapsack_unbounded([2], [3], 4)  # 6: the item twice

The loop body is the same; only the direction differs, and the two
versions solve different problems. When converting a 2-D table to
one row, draw the arrows: if a cell reads cells to its left in the
OLD row, loop from right to left.

LCS in one row needs one extra variable, because it reads the
diagonal L[i-1][j-1], which was overwritten one step earlier:

    def lcs_one_row(x, y):
        row = [0] * (len(y) + 1)
        for i in range(1, len(x) + 1):
            diag = 0                    # L[i-1][j-1]
            for j in range(1, len(y) + 1):
                saved = row[j]          # L[i-1][j], about to change
                if x[i - 1] == y[j - 1]:
                    row[j] = diag + 1
                else:
                    row[j] = max(row[j], row[j - 1])
                diag = saved
        return row[len(y)]

    lcs_one_row("BACDB", "BDCB")  # 3

7.4 Dropping a dimension from a 3-D table
-----------------------------------------

The same idea works one level up. In lcs3, layer i reads only layer
i - 1, so two 2-D layers are enough: O(q·r) space instead of
O(p·q·r).

    def lcs3_two_layers(a, b, c):
        q, r = len(b), len(c)
        prev = [[0] * (r + 1) for _ in range(q + 1)]
        for i in range(1, len(a) + 1):
            curr = [[0] * (r + 1) for _ in range(q + 1)]
            for j in range(1, q + 1):
                for k in range(1, r + 1):
                    if a[i - 1] == b[j - 1] == c[k - 1]:
                        curr[j][k] = prev[j - 1][k - 1] + 1
                    else:
                        curr[j][k] = max(prev[j][k], curr[j - 1][k],
                                         curr[j][k - 1])
            prev = curr
        return prev[q][r]

Floyd-Warshall goes further and keeps a single 2-D table, updated in
place. That is safe because pass k never changes row k or column k:
d[i][k] + d[k][k] is just d[i][k], since d[k][k] = 0.

7.5 Store only the reachable states
-----------------------------------

A memo dict stores only the states the recursion actually visits.
When most of a big table can never be reached, that is far smaller
than a full list. The bottom-up version keeps each layer as a set or
dict of the states that exist:

    def reachable_sums(nums):
        sums = {0}
        for x in nums:
            sums |= {s + x for s in sums}
        return sums

    reachable_sums([100, 250, 400])
    # {0, 100, 250, 350, 400, 500, 650, 750}: 8 states, not 751

The trade-off is speed per state: a dict lookup is several times
slower than a list index. Use it when the table is sparse.

7.6 Getting the choices back without the full table
---------------------------------------------------

Rolling rows lose the trace back of step 5. There are three ways to
recover it.

* Keep only the decisions, compactly
    Store one byte per cell (took the item or not) in a bytearray,
    and keep the values in a single row. A list slot holds an 8-byte
    reference (plus the int it points to), so this is about 8 times
    smaller than keeping all the values.

        def knapsack_with_items(weights, values, cap):
            n = len(weights)
            best = [0] * (cap + 1)
            took = [bytearray(cap + 1) for _ in range(n)]
            for i in range(n):
                w, v = weights[i], values[i]
                for c in range(cap, w - 1, -1):
                    if best[c - w] + v > best[c]:
                        best[c] = best[c - w] + v
                        took[i][c] = 1
            items, c = [], cap
            for i in range(n - 1, -1, -1):
                if took[i][c]:
                    items.append(i)
                    c -= weights[i]
            return best[cap], items[::-1]

        knapsack_with_items([1, 3, 4, 5], [1, 4, 5, 7], 7)
        # (9, [1, 2]): items B and C

* Checkpoints
    Save every s-th row while filling the table forward. To trace
    back, recompute the rows between two checkpoints from the earlier
    one. With s about the square root of the number of rows, this
    uses O(sqrt(m) · n) space for about twice the time.
* Divide and conquer (Hirschberg's algorithm)
    For LCS and edit distance, compute the middle row of the table
    from the top and again from the bottom (on the reversed strings).
    The best place for the answer to cross the middle row splits the
    problem into two halves, which are solved the same way. The
    result is an actual LCS in O(m·n) time but only O(min(m, n))
    space. Alignment tools for very long DNA sequences use this idea.

7.7 Summary
-----------

Technique         Use it when                         Space
----------------  ----------------------------------  ---------------
Few variables     dp[i] reads a fixed number back     O(1)
Two rows          row i reads only row i - 1          one row x 2
One row           and you pick the loop direction     one row
Shorter axis      two sequences of unequal length     O(min(m, n))
Two layers        a 3-D layer reads only the last     2-D layer x 2
Reachable states  most of the table is unreachable    states visited
Decision bytes    you need trace back, low memory     1 byte per cell
Hirschberg        you need the LCS of huge strings    O(min(m, n))

A good order of work: get the full-table version right, keep it as a
test oracle, then shrink the space and check that the answers match.

8. HANDLING COMPLEX CONSTRAINTS
===============================

Real problems add rules: take at most k of something, never two in a
row, wait a day after selling, a capacity of a billion, numbers that
can be negative. There are two levers for handling them.

* Part A, tweak the state definition
    Make the state record what the rule depends on, or reshape it so
    the table stays small.
* Part B, optimize the state transitions
    Keep the state, but make each transition cheaper, so that
    (number of states) x (work per state) goes down.

PART A: TWEAKING THE STATE DEFINITION
-------------------------------------

8.1 A counter dimension for "at most k" rules
.............................................

If a rule limits how many times something may happen, add an index
that counts it. Knapsack with at most m items: best[j][c] = the best
value using at most j items with weight at most c.

    def knapsack_max_items(weights, values, cap, m):
        best = [[0] * (cap + 1) for _ in range(m + 1)]
        for w, v in zip(weights, values):
            for j in range(m, 0, -1):           # downward, as in 7.3
                for c in range(cap, w - 1, -1):
                    take = best[j - 1][c - w] + v
                    best[j][c] = max(best[j][c], take)
        return best[m][cap]

    knapsack_max_items([1, 3, 4, 5], [1, 4, 5, 7], 7, 1)  # 7: D
    knapsack_max_items([1, 3, 4, 5], [1, 4, 5, 7], 7, 2)  # 9: B + C

The item index has already been rolled away (section 7.3), so the
"3-D" table is stored as 2-D. Both the count loop and the capacity
loop run downward, so each item is used at most once.

8.2 A small "mode" dimension for rules about neighbors
......................................................

If a rule depends on what happened at the previous step, add an index
with a few values that describe the recent past. Paint a row of
houses so that no two neighbors have the same color, at the lowest
total cost:

    def paint_houses(cost):
        prev = [0] * len(cost[0])     # prev[c]: cheapest, ends in c
        for row in cost:
            curr = []
            for c in range(len(row)):
                others = [prev[d] for d in range(len(row)) if d != c]
                curr.append(row[c] + min(others))
            prev = curr
        return min(prev)

    paint_houses([[17, 2, 17], [16, 16, 5], [14, 3, 19]])
    # 10: colors 1, 2, 1 (from 0) cost 2 + 5 + 3

The state is (house, color of that house). In general, write the rule
as a small state machine. Each mode is one value of the new index,
and each allowed arrow between modes is a transition. Stock trading
with a one-day cooldown, for example, has the modes "holding",
"just sold" and "resting". max_non_adjacent in 7.1 is the same idea
with two modes, take and skip.

8.3 Swap the roles of index and value
.....................................

If one index has a huge range, look for another quantity with a
small range and make that the index. In knapsack with a capacity of
a billion, a capacity index is hopeless. If the values are small,
index by value instead: least[t] = the smallest weight that reaches a
total value of exactly t.

    def knapsack_by_value(weights, values, cap):
        INF = float("inf")
        total = sum(values)
        least = [0] + [INF] * total
        for w, v in zip(weights, values):
            for t in range(total, v - 1, -1):
                least[t] = min(least[t], least[t - v] + w)
        return max(t for t in range(total + 1) if least[t] <= cap)

    knapsack_by_value([1, 3, 4, 5], [1, 4, 5, 7], 7)          # 9
    knapsack_by_value([10**9, 2 * 10**9], [3, 5], 2 * 10**9)  # 5

The second call has capacity 2,000,000,000, but its table has only
sum(values) + 1 = 9 cells. The running time is O(n · sum of values)
instead of O(n · capacity).

8.4 Shift the index when values can be negative
...............................................

Put a + or - in front of each number so that the total equals a
target. Partial sums range from -S to S, where S is the sum of the
numbers. List indices must not be negative, so store sum s at index
s + S:

    def target_sum_ways(nums, target):
        S = sum(nums)
        if abs(target) > S:
            return 0
        ways = [0] * (2 * S + 1)     # ways[s + S]: ways to reach s
        ways[S] = 1
        for x in nums:
            new = [0] * (2 * S + 1)
            for s in range(2 * S + 1):
                if ways[s]:
                    new[s + x] += ways[s]
                    new[s - x] += ways[s]
            ways = new
        return ways[target + S]

    target_sum_ways([1, 1, 1, 1, 1], 3)  # 5

Be careful in Python: dp[-1] does not raise an error, it silently
reads the LAST element. A forgotten offset gives wrong answers, not a
crash. A dict keyed by the real sum is the other way out.

8.5 Drop state variables that can be computed
.............................................

If one state variable can be computed from the others, remove it.
Two people walk from the top-left to the bottom-right corner of a
grid at the same time, each moving one step right or down per turn.
The obvious state is (r1, c1, r2, c2): 4-D. But after t turns,
r + c = t for both people, so (t, r1, r2) determines the rest: 3-D,
and a factor of n smaller.

A related trick is a band. Edit distance with at most k edits only
ever needs cells with |i - j| <= k, because any other cell already
costs more than k. Filling only that diagonal band takes O(n · k)
time instead of O(n^2).

8.6 Record a set as a bitmask
.............................

If a rule depends on WHICH items have been used, not just how many,
the state must record a set. For small n, store it as the bits of an
integer, as in the traveling salesperson problem (section 9).

8.7 Forbid states instead of adding dimensions
..............................................

A rule that only rules out some states does not need a new index.
Give the forbidden states an impossible value: infinity for a
minimum, minus infinity for a maximum, or 0 for a count. A blocked
cell in a grid-paths problem has 0 paths.

The base case is where this kind of tweak most often goes. Knapsack
asks for weight AT MOST c. To require the knapsack to be EXACTLY
full, change only the initial row:

    best = [0] * (cap + 1)                  # at most c
    best = [0] + [float("-inf")] * cap      # exactly c

With -inf, a capacity can only reach a finite value by being built
up from best[0] one exact item at a time.

PART B: OPTIMIZING STATE TRANSITIONS
------------------------------------

The cost of a DP is (number of states) x (work per state). If dp[i]
looks back at k earlier states, the total is O(n · k). Many
transitions are a sum, minimum or maximum over a range of earlier
states, and each of these has a faster way.

8.8 Prefix sums for a sum over a range
......................................

You can climb 1, 2, ..., or k stairs at a time. Then ways[i] is the
sum of ways[i-k] through ways[i-1]: O(n · k) if you add them up each
time. A prefix-sum array gives each range sum in O(1):

    def climb_ways(n, k):
        ways = [0] * (n + 1)
        ways[0] = 1
        prefix = [0] * (n + 2)   # prefix[i] = ways[0] + ... ways[i-1]
        prefix[1] = 1
        for i in range(1, n + 1):
            ways[i] = prefix[i] - prefix[max(0, i - k)]
            prefix[i + 1] = prefix[i] + ways[i]
        return ways[n]

    climb_ways(10, 3)  # 274

The time is O(n) for any k.

8.9 A monotonic deque for a maximum over a sliding window
.........................................................

Start on the first square of a row of numbers and jump 1 to k squares
at a time until you reach the last one, maximizing the sum of the
squares you land on. Then dp[i] = nums[i] + the maximum of dp[i-k]
through dp[i-1]. Keep a deque of indices whose dp values decrease
from front to back. Its front is always the maximum of the window:

    from collections import deque

    def max_jump_score(nums, k):
        dp = [0] * len(nums)
        dp[0] = nums[0]
        window = deque([0])        # indices, dp values decreasing
        for i in range(1, len(nums)):
            while window[0] < i - k:
                window.popleft()   # fell out of the window
            dp[i] = nums[i] + dp[window[0]]
            while window and dp[window[-1]] <= dp[i]:
                window.pop()       # can never be the maximum again
            window.append(i)
        return dp[-1]

    max_jump_score([1, -1, -2, 4, -7, 3], 2)  # 7  (1 - 1 + 4 + 3)

Each index enters and leaves the deque at most once, so the total
time is O(n) instead of O(n · k). Use the same structure for a
minimum by flipping the comparison.

8.10 Binary search over a sorted helper array
.............................................

The slow LIS takes O(n^2): dp[i] = 1 + the largest dp[j] over j < i
with nums[j] < nums[i]. Redefine the state instead: tails[L] = the
smallest value that can end an increasing subsequence of length
L + 1. The list tails is always sorted, so each new number is placed
with a binary search:

    from bisect import bisect_left

    def lis_length(nums):
        tails = []
        for x in nums:
            pos = bisect_left(tails, x)
            if pos == len(tails):
                tails.append(x)
            else:
                tails[pos] = x
        return len(tails)

    lis_length([10, 9, 2, 5, 3, 7, 101, 18])  # 4

The time is O(n log n). This uses both levers: the state swaps index
and value (length as the index, as in 8.3), which is what makes the
fast binary-search transition possible.

8.11 A running best instead of rescanning
.........................................

If the range is "every earlier state", with no other condition, keep
the best value seen so far in one variable. To buy a stock once and
sell it later for the largest profit:

    def best_profit(prices):
        lowest, best = float("inf"), 0
        for p in prices:
            best = max(best, p - lowest)
            lowest = min(lowest, p)
        return best

    best_profit([7, 1, 5, 3, 6, 4])  # 5  (buy at 1, sell at 6)

The O(n^2) scan of every buy day becomes O(n).

8.12 Split repeated items into power-of-two bundles
...................................................

In the bounded knapsack, item i can be taken up to count[i] times.
Treating it as count[i] separate 0/1 items costs O(count) per item.
Instead, split the copies into bundles of 1, 2, 4, ... plus a
remainder. Any number of copies from 0 to count can be made from
those bundles, so O(log count) bundles are enough:

    def bounded_knapsack(weights, values, counts, cap):
        best = [0] * (cap + 1)
        for w, v, left in zip(weights, values, counts):
            size = 1
            while left > 0:
                take = min(size, left)   # one bundle of take copies
                bw, bv = take * w, take * v
                for c in range(cap, bw - 1, -1):
                    best[c] = max(best[c], best[c - bw] + bv)
                left -= take
                size *= 2
        return best[cap]

    bounded_knapsack([3], [5], [10], 20)  # 30: six copies

The 10 copies become bundles of 1, 2, 4 and 3: four 0/1 items
instead of ten.

8.13 Advanced optimizations (names to recognize)
................................................

These need a proof that their condition holds, which is beyond this
course. They are worth recognizing by name.

* Convex hull trick
    For transitions of the form min over j of (a[j] · x[i] + b[j]),
    which is a minimum over a set of lines.
* Knuth's optimization
    For interval DPs whose best split point moves monotonically,
    such as the optimal binary search tree: O(n^3) becomes O(n^2).
* Divide-and-conquer optimization
    For dp[i] = min over j of cost(j, i), when the best j never
    decreases as i grows.

8.14 A checklist for a new constrained problem
..............................................

1. Write the plain recurrence and ignore the hard rule at first.
2. For each rule, ask what it depends on.
   * Does it forbid some states? Use an impossible value (8.7).
   * Does it count something? Add a counter (8.1).
   * Does it depend on the previous step? Add a mode (8.2).
   * Does it depend on a set? Use a bitmask (8.6).
3. Count the states. If one index has a huge range, swap index and
   value (8.3), or drop variables that can be computed (8.5).
4. Look at the inner loop of each transition.
   * A sum over a range: prefix sums (8.8).
   * A max or min over a sliding range: a monotonic deque (8.9).
   * A search in a sorted helper array: binary search (8.10).
   * Every earlier state: a running best (8.11).
5. Only then shrink the space (section 7), and check the answers
   against the full-table version.

9. WHEN ONE DIMENSION IS EXPONENTIAL: BITMASK DP
================================================

Sometimes the state has to record a set. The traveling salesperson
problem asks for the shortest tour that visits n cities once each.

    dp[mask][j] = shortest path that starts at city 0, visits exactly
                  the cities in the set mask, and ends at city j

Here mask is an integer whose bits mark the visited cities, so this
dimension has 2^n values. There are 2^n · n states and each tries n
next cities: O(2^n · n^2) time. That is still exponential, but for
n = 20 it is about 400 million steps, compared with 19! (about
1.2 x 10^17) possible orderings for brute force.

10. PYTHON PITFALLS WITH MULTIDIMENSIONAL TABLES
================================================

* Aliased rows
    [[0] * 3] * 2 makes two references to the SAME row:

        bad = [[0] * 3] * 2
        bad[0][0] = 9        # bad  is [[9, 0, 0], [9, 0, 0]]
        good = [[0] * 3 for _ in range(2)]
        good[0][0] = 9       # good is [[9, 0, 0], [0, 0, 0]]

    Build every level except the innermost with a comprehension.
* Index order
    Pick one order (L[i][j][k]) and use it in the allocation, the
    loops and the recurrence. Mixing up j and k is easy in 3-D.
* Off-by-one in every dimension
    Each index needs size n + 1 for its base case, and row i refers
    to item or letter i - 1.
* Memory
    A Python list slot holds an 8-byte reference, so a table of 100
    million cells needs close to 1 GB. Reduce dimensions (section 7)
    or use memoization when only a few states are reachable.

11. PRACTICE
============

* Exactly k items with a given sum
    Count the ways to choose exactly k numbers from a list that add
    up to S. State: dp[i][j][s] = ways using the first i numbers,
    choosing j of them, with sum s.
    Check: from [1, 2, 3, 4, 5], choosing 2 that sum to 6 gives 2
    ways ({1, 5} and {2, 4}).
* Houses on a circle
    The largest sum with no two adjacent numbers chosen, where the
    first and last numbers also count as adjacent. Hint: reuse
    max_non_adjacent from 7.1 twice.
    Check: [2, 3, 2] gives 3, and [1, 2, 3, 1] gives 4.
* Stock trading with a cooldown
    Buy and sell as often as you like, holding at most one share,
    but after a sale you must wait one day before buying again. Use
    the three modes from 8.2.
    Check: prices [1, 2, 3, 0, 2] give a profit of 3.
* Space challenge
    Rewrite lcs3 to use O(q·r) space, then O(r) space. Which values
    must you save before overwriting them? (See 7.3 and 7.4.)
* Trace back for three strings
    Extend lcs3 to return the subsequence itself, the way lcs_string
    does for two strings.

Bug                                     Fix
--------------------------------------  ------------------------------
Default memo={} shared by every call    Use memo=None, or @lru_cache

Cell read before it is filled           Check each cell’s dependencies
                                        come first

Speaker notes:

  the recipe for one problem, then reveal. Grid paths: p[r][c] is the
  number of ways to reach cell (r, c); the first row and first column
  are all 1; for a 3 × 7 grid the answer is 28. Edit distance: d[i][j]
  is the cost of turning the first i letters of one word into the
  first j letters of the other; if the letters match it is
  d[i−1][j−1], otherwise 1 + the minimum of the delete, insert and
  substitute options; kitten to sitting is 3 (substitute k→s,
  substitute e→i, insert g). LIS: dp[i] = 1 + the maximum dp[j] over
  earlier j with a smaller value; one answer is 2, 3, 7, 18, length 4.
  Solutions for all three are in dynamic_programming_examples.py.
  These work well as an in-class lab or optional homework.

----------------------------------------------------------------------
EXPANSION G: WRITING UP A DP SOLUTION (HANDOUT)
----------------------------------------------------------------------

[Handout or homework guide · no class time]

A complete DP answer on homework or an exam has seven parts. Most
lost points come from leaving out part 1 or part 6.

1. Subproblem: what one table entry means, in a full sentence.
2. Recurrence: the formula, with every case.
3. Base cases.
4. Evaluation order: why each entry's dependencies are ready.
5. Where the final answer is in the table.
6. Running time and space: states x work per state, with the
   numbers filled in.
7. Correctness, in a few sentences: why the recurrence considers
   every possible last choice.

A sample answer: count the ways to climb n stairs taking 1 or 2
steps at a time.

    1. ways[i] = the number of different step sequences that reach
       stair i exactly.
    2. ways[i] = ways[i-1] + ways[i-2] for i >= 2.
    3. ways[0] = 1 (the empty sequence) and ways[1] = 1.
    4. Increasing i: ways[i] needs only the two entries before it.
    5. ways[n].
    6. n + 1 states, O(1) work each: O(n) time. O(n) space, or O(1)
       with two variables.
    7. Every sequence that reaches stair i ends with a 1-step from
       stair i-1 or a 2-step from stair i-2, never both, so the two
       counts add with no overlap and nothing is missed.

    For n = 5 the table is 1, 1, 2, 3, 5, 8, so there are 8 ways.

[Takeaways]

RECURSION + MEMORY
==================

* Check two properties
    Overlapping subproblems and optimal substructure.

* Follow the recipe
    Subproblem, recurrence, base cases, order, answer.

* Exponential to polynomial
    Time ≈ number of states × work per state.

    AdditionalLectures/dynamic_programming_examples.py

Speaker notes:
  Close with the three ideas. First, DP applies when subproblems
  repeat and the best answer is built from best sub-answers. Second,
  the five-step recipe; step 1, defining the subproblem in words, is
  where to spend your time. Third, to estimate the running time, count
  the states (cells in the table) and multiply by the work per state:
  n for Fibonacci, A·k for coins, n·C for knapsack, m·n for LCS. Point
  students to the example file: python3
